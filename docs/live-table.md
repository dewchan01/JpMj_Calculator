# Table-first match flow

## Call sounds

Others > Sound effects provides a persistent on/off preference and previews for Pon, North extraction,
Chi, open/added/concealed Kan, Riichi, Double Riichi, Ron and Tsumo. Call buttons play immediately when pressed, before tile entry or storage completes. Riichi plays
after declaration validation and before saving; Ron/Tsumo play when selected (or after the generic
winner selection). Confirming tiles or settlement does not replay the call. Undo and reloads are silent. Audio failures never prevent saving a game action.

Playback prefers six bundled Ichihime MP3 clips downloaded from the user-selected Myinstants pages.
Open, added and concealed Kan share the Kan clip. North and Double Riichi use an available local
Japanese device voice through the [Web Speech API](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/getVoices),
then generated tones if unavailable. Playback failure also uses this fallback. Clips are cached
offline and interrupted when muted or replaced by another call.

See [source and rights notes](../apps/web/public/sounds/ichihime/SOURCES.md). Download availability
is not an open license; no open redistribution license was identified on the source pages.

`/score` remains the independent quick calculator. `/score/:id` now opens the live table: player balances, round, Honba, escrow, timer, indicator control, dice and point differences. The main table fits the viewport at supported phone and desktop sizes; detailed operations open native dialogs. Very short viewports, large accessibility text and long histories can still require scrolling inside dialogs.

The home page stores reusable player names in `riichi-players-v1` in localStorage. Each seat opens the same Saved players dialog instead of a dropdown and separate name input. The picker supports search, ascending/descending name order, newest-added order and an independently scrolling list that loads another 24 players near its end without pagination. Already-seated names are disabled for other seats. A floating + opens a separate creation prompt over the picker. Close/Cancel retains the picker; Add saves and selects the player for a chosen seat. Cancel precedes Add below the name field. Mobile home/filter prompts slide up/down; desktop uses centered dialogs. Each table keeps stable local player IDs for balances and historical settlements. Removing a saved player does not delete existing games. Records currently aggregate by name, as before.

The setup toolbar is a single row of labelled icon buttons outside and above the setup card. It opens Saved players, a two-seat Quick swap dialog, Random positions, and the dice simulator. Swapping or shuffling moves only the active 3P/4P names; a fourth saved setup name stays untouched while in 3P. Empty active names become their displayed default player names before moving. Saved-player selectors follow the new seat assignments. Setup and live games share the same animated, reduced-motion-aware dice component.

Each player has visible Riichi and Call buttons. North extraction is available only inside the 3P player-action prompt. The Riichi button below the player declares ordinary Riichi immediately (1,000-point deposit); clicking an active Riichi button cancels the current declaration and refunds 1,000 points immediately, without a prompt. Player actions offers a separate Double Riichi button: it sits below Open Kan and records a user-confirmed uninterrupted first-turn declaration. Turn/discard order is not tracked, so a closed player can record it after other calls were entered; these recorded calls still interrupt Ippatsu. Already declared or open players cannot declare again. The same prompt has a separate Ron/Tsumo section preselecting that player; Ron still chooses a discarder, but does not repeat the winner selector when entered from a player box; hand/settlement validation is unchanged. Meld removal uses labelled trash icons. North extraction records immediately without another confirmation; extracted North tiles are visible beside labelled plus/minus controls in the player prompt. Pon and open/concealed Kan can be entered with one representative tile; the remaining matching copies are generated with unique IDs. For Pon, choose a red five when the set contains one; only one generated copy is red. With red fives enabled, every five Kan (open, concealed or added) automatically contains exactly one red five, even when ordinary five input is used. An added Kan preserves the original Pon and marks the fourth tile red only if needed. Disabled-red rules remain ordinary; duplicate physical tiles are still rejected. Chi still needs its sequence and added Kan its fourth tile. Full-set notation remains accepted. The editor explains the required shape and disables Done for invalid one-tile/full-set, Chi sequence or Kakan fourth-tile input.

Live player cards face the centre from their current display positions, including after a seat swap. All four cards use the same gap from the centre control, with a bordered Riichi-stick lane reserved even before a declaration. Seat wind, dealer and the Yakitori skewered-bird marker sit above and outside the score box. Riichi and Call buttons sit below it, show an active colour, and include call counts. Dealer and Yakitori markers have individual borders. Tap the player box for actions. Hold its internal ± icon to keep that player's actual score and show signed differences on the other players (other player minus selected player). Release, pointer cancellation, focus loss or a window switch restores actual scores. Keyboard users can hold Space or Enter. This only changes the display.

The centre action is a round checkmark button, labelled End this hand for assistive technology (Final results after the match ends). A larger round/Honba/escrow strip and the timer stay at the top. Dora and Ura previews occupy a compact row below the table; each opens its tile-entry sheet directly, without an intermediate prompt. Done validates and saves only that indicator; dismissing the sheet discards the draft. Kan opens the Dora editor. Dice and the game menu sit at the bottom. Phone views have additional padding. The dedicated Riichi prompt excludes call buttons and recorded melds. Holding ± changes only the numbers and icon state, without outlining the player box; the old separate point-difference strip is no longer shown.

My table in the game menu saves a paused clock before returning home. Reopening an unfinished game automatically resumes its clock. In-game settings shows all six groups of the match's saved rule snapshot, including 3P/4P-specific fields, instead of a point-difference toggle or a link to global settings. All groups are shown directly with compact headings and no collapse controls. Historical rule snapshots remain immutable.

The local Yakitori marker is a simplified SVG adaptation of [Mahjong yakitori.jpg by Cangjie6](https://commons.wikimedia.org/wiki/File:Mahjong_yakitori.jpg), distributed under CC BY-SA 4.0. Attribution and adaptation details are retained in `public/icons/yakitori-LICENSE.txt` and appended to the deployed third-party notices; the marker is included in the existing offline icon cache.

Chi automatically uses the previous seat as its source; no source selection is needed. The active Riichi button cancels the declaration directly during the current hand. Cancelling refunds that player's 1,000-point deposit, clears their Riichi/Double Riichi state, and preserves other declarations and calls. The cancellation itself can be undone; older edit snapshots are cleared to prevent restoring the removed deposit accidentally. Settled declarations remain part of the hand history.

Undo previous action in the game menu restores up to 30 recent current-hand edits, including calls, North, indicators and Riichi escrow. The undo stack survives reloads and does not rewind the clock. Settling a hand clears it; settled-hand reversal remains in History.

Tap a player to declare Riichi (an escrow deposit), record Chi/Pon/open Kan/concealed Kan/added Kan or, in 3P, extract North. Calls store actual tiles, source, called tile, original order and original Pon metadata when upgraded. Double Riichi and a post-Riichi concealed Kan require explicit condition declarations. The app does not simulate discards, legal timing, waits before/after Kan or remaining wall tiles, so these conditions still need the players' judgement. Revealed physical copies and Sanma tile restrictions are checked before saving. All Kan actions offer indicator editing.

End this hand asks for win versus draw. A win collects the winner(s), method, discarder, each winner's concealed tiles and winning tile, then applicable conditions. Recorded melds, North, Riichi and indicators are supplied automatically. Ippatsu is not offered after a recorded interrupting call. Multiple Ron uses the saved all-win/head-bump/triple-abort policy. Claims such as first-turn Yakuman, robbed North, robbed concealed Kan and Kita replacement draws go through the existing scoring validation. Only validated results reach a payment preview and settlement.

An exhaustive/abortive/Nagashi draw asks for the corresponding declarations; M.League excludes the latter two. Settlements retain scoring inputs, results, chip deltas, live actions, per-hand duration and the reversible previous/next round state. Automatic match endings and manual End entire match share final Yakitori/escrow handling. Manual ending does not invent a score for an unfinished hand. Final standings then use the immutable saved Uma/Oka/rounding/betting/chip settings.

The clock stores accumulated milliseconds, the current running start and the hand's accumulated-time baseline. Reloads preserve a running or paused clock. Paused time is excluded. Undo pauses the table and restores the prior hand state; resume before continuing. Old tables without a clock start timed recording when opened; earlier elapsed time cannot be reconstructed accurately. Records use the clock when available and retain the legacy date-based duration estimate otherwise.

The floating menu opens pause/resume, current-hand ending, entire-match ending, history/export/undo, game information, in-game display preferences, display seating and help. Swapping seats changes positions only; player IDs, seat winds, dealer, balances, initial tie priority and scoring history remain unchanged. Point differences use the selected player as the baseline. Dice use unbiased rejection sampling from the browser's random bytes.

Records show completed games only. Clicking anywhere on a game card opens `/records/:id`, a results page without live table controls. The home page's Ongoing games dialog lists unfinished games and resumes a selected table. Record results only uses the selected home-page rules and players to save final points without inventing individual hands.

Record results only and Ongoing games sit together below the home setup card. Manual results accept a local game date/time, defaulting to now; saved and edited dates are persisted as timestamps and displayed using the current language. Record cards omit redundant completion badges and management buttons. The opened result page has pencil/delete icons at the top right: pencil opens the shared point/date editor dialog, while delete opens a confirmation. Player-profile date/mode filtering also uses a shared dialog with draft values applied explicitly. Dialog close controls use the same neutral bordered X; select focus uses an inset underline instead of the outer focus ring. The Records sticky controls retain the page's top gutter while scrolling.

Each player row opens `/records/player/:name`, retaining the date/mode filters. Overview shows the last 16 chronological game ranks, rank histogram, recent versus preceding 16-game blocks, observed playing rates, population rank variance and a normalized stability score, and winning-receipt bins. Statistics includes the requested state-conditional win, deal-in, open, Riichi, dealer and draw-Tenpai measures; comparison values use the same dates and player count. Score means the Uma/Oka-adjusted result; points mean net raw-point changes. Money is aggregated separately per currency. Explore shows shared-opponent average rank/score and strict finish-ahead rate, shared game links, player comparison curves and seat analysis. Game rank uses starting seats; hand rates use the dealer/seat stored in each event. Three-player and four-player records never mix. Fourth-place measures are unavailable in 3P.

State metrics use the settlement snapshot, recorded scoring inputs and Riichi deposits. Dama means closed without Riichi; an Ankan does not make a hand open. Unknown metadata is excluded from the corresponding denominator rather than treated as false. Vs-state rates use hands exposed to at least one opponent in the state; multiple Ron counts once per state and combines payments within that state. Final Yakitori/escrow awards and score corrections do not become hand win/deal-in receipts. Tenpai uses exhaustive draws only. Renchan is the additional continuing hands per recorded dealer run, including continuation after an abortive draw. Stability is 100 × (1 − rank variance / ((player count − 1)² / 4)), bounded to 0–100 and unavailable with fewer than two games; it measures variability rather than skill.

M.League resemblance is an offline, versioned comparison against eight reference players from the official 2026–27 regular-season statistics at https://m-league.jp/stats/, retrieved 2026-10-26. It requires 20 recorded 4P hands with known states/outcomes and at least three available metrics. The UI links the source and explains normalized RMS distance, included metrics/scales, snapshot date and its descriptive rather than skill-rating meaning. Rules/payment conventions and early-season sample sizes can differ. No current/live league-data claim is made.

Final results have Result, History and Details tabs. Result offers compact standings and a metric-by-player comparison table without per-player Details buttons. The pencil opens final-point/date editing. Corrections conserve the table total, append a scoreAdjustment ledger event, update ranks and settlement amounts, and preserve the original hand history. History uses compact expandable rows. Event summaries show the round, time and nonzero point changes. Players share a horizontal row with vertical dividers. Points and recorded Riichi/meld/North markers appear below each name; selecting a player fills the shared details area below. The event chevron sits on the right. Details groups statistics by metric; the player chips filter both the graph and the metric cards. The statistics exclude corrections and abortive draws from completed-hand denominators; Tenpai rates use exhaustive draws with recorded declarations. Missing legacy declarations are unavailable rather than zero. Win/deal-in averages exclude final Yakitori penalties and final escrow adjustments; normal hand Honba and awarded Riichi sticks are included in win receipts. Average winning streak is the mean length of consecutive winning runs. Multiple Ron counts as one deal-in hand for its discarder.

Share image creates a PNG of the graph, ranks and statistics (all players, or the selected player), uses native file sharing when available, and otherwise downloads the PNG. Games remain automatically saved during play; Save game retains the record and opens Records, while Discard game requires confirmation and removes the game and its draft. Root dialogs dismiss on a backdrop click; dialogs with a previous step, and nested dialogs, remain open. Dice are rerolled by clicking the dice, animate all six cube faces and settle to flat result faces.

## Editing any recorded hand

In the live-table History panel, expand a win/draw and select Edit hand. The draft restores that
hand's round, balances, escrow and recorded live calls. Re-enter win/draw, winners, discarder, tiles
and conditions; player buttons allow call/Riichi changes. These changes stay in memory until the
replacement settlement is confirmed. Cancel, Close, Escape or navigation leaves stored data unchanged.

Saving recalculates every subsequent recorded win/draw using its saved scoring inputs and the new
dealer, round, Honba and escrow. Points, chips, progression and final penalties/escrow are rebuilt.
Current unfinished-hand calls are retained. The repository performs one version-checked save after
all recalculation succeeds. Hand IDs, original dates and duration are preserved; previous versions
are kept in revisions on the edited ledger event. This differs from latest-event undo and the
final-point adjustment prompt.

If a later hand lacks scoring inputs, a later Riichi deposit is no longer affordable, or the edit
would end the match before another recorded hand, saving fails without modifying stored data.
Legacy entries without a round snapshot are not offered Edit hand.
