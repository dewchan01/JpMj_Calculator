# Table-first match flow

`/score` remains the independent quick calculator. `/score/:id` now opens the live table: player balances, round, Honba, escrow, timer, indicator control, dice and point differences. The main table fits the viewport at supported phone and desktop sizes; detailed operations open native dialogs. Very short viewports, large accessibility text and long histories can still require scrolling inside dialogs.

The home page stores reusable player names in `riichi-players-v1` in localStorage. Manage names in the Saved players dialog, whose Return button stays at the top. Choosing a name fills a seat; manual names remain supported. Each table keeps stable local player IDs for balances and historical settlements. Removing a saved player does not delete existing games. Records currently aggregate by name, as before.

Each player has visible Riichi and Call buttons, plus Kita in 3P. Pon and open/concealed Kan can be entered with one representative tile; the remaining matching copies are generated with unique IDs. Choose a red five when the set contains one; only one generated copy is red. Chi still needs its sequence and added Kan its fourth tile. Full-set notation remains accepted.

Chi automatically uses the previous seat as its source; no source selection is needed. A player's Riichi dialog also offers cancellation during the current hand. Cancelling refunds that player's 1,000-point deposit, clears their Riichi/Double Riichi state, and preserves other declarations and calls. The cancellation itself can be undone; older edit snapshots are cleared to prevent restoring the removed deposit accidentally. Settled declarations remain part of the hand history.

Undo previous action in the game menu restores up to 30 recent current-hand edits, including calls, North, indicators and Riichi escrow. The undo stack survives reloads and does not rewind the clock. Settling a hand clears it; settled-hand reversal remains in History.

Tap a player to declare Riichi (an escrow deposit), record Chi/Pon/open Kan/concealed Kan/added Kan or, in 3P, extract North. Calls store actual tiles, source, called tile, original order and original Pon metadata when upgraded. Double Riichi and a post-Riichi concealed Kan require explicit condition declarations. The app does not simulate discards, legal timing, waits before/after Kan or remaining wall tiles, so these conditions still need the players' judgement. Revealed physical copies and Sanma tile restrictions are checked before saving. All Kan actions offer indicator editing.

End this hand asks for win versus draw. A win collects the winner(s), method, discarder, each winner's concealed tiles and winning tile, then applicable conditions. Recorded melds, North, Riichi and indicators are supplied automatically. Ippatsu is not offered after a recorded interrupting call. Multiple Ron uses the saved all-win/head-bump/triple-abort policy. Claims such as first-turn Yakuman, robbed North, robbed concealed Kan and Kita replacement draws go through the existing scoring validation. Only validated results reach a payment preview and settlement.

An exhaustive/abortive/Nagashi draw asks for the corresponding declarations; M.League excludes the latter two. Settlements retain scoring inputs, results, chip deltas, live actions, per-hand duration and the reversible previous/next round state. Automatic match endings and manual End entire match share final Yakitori/escrow handling. Manual ending does not invent a score for an unfinished hand. Final standings then use the immutable saved Uma/Oka/rounding/betting/chip settings.

The clock stores accumulated milliseconds, the current running start and the hand's accumulated-time baseline. Reloads preserve a running or paused clock. Paused time is excluded. Undo pauses the table and restores the prior hand state; resume before continuing. Old tables without a clock start timed recording when opened; earlier elapsed time cannot be reconstructed accurately. Records use the clock when available and retain the legacy date-based duration estimate otherwise.

The floating menu opens pause/resume, current-hand ending, entire-match ending, history/export/undo, game information, in-game display preferences, display seating and help. Swapping seats changes positions only; player IDs, seat winds, dealer, balances, initial tie priority and scoring history remain unchanged. Point differences use the selected player as the baseline. Dice use unbiased rejection sampling from the browser's random bytes.
